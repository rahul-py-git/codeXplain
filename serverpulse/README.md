# ServerPulse — Server Monitoring Tool

ServerPulse is a small, beginner-friendly REST API that reports the current machine's CPU, memory, disk usage, uptime, and threshold-based alerts. It is a learning project for Python, Linux, APIs, testing, and production-support fundamentals.

## What it does

- `GET /health`: confirms that the API process is responding.
- `GET /metrics`: returns a snapshot of machine resource usage.
- `GET /alerts`: returns warnings when configured resource thresholds are reached.
- Uses `psutil` to read operating-system metrics and FastAPI to expose them as JSON.
- Includes unit tests for alert logic.

> **Safety:** This first version is intended for local learning. It has no authentication, TLS, or multi-host agent. Do not expose it directly to the public internet. Run it only on a trusted machine and add authentication before deployment.

## Requirements

- Python 3.10 or newer
- Internet access once, to install packages
- Windows, macOS, or Linux; Linux provides the most relevant server-monitoring practice

## Run on Windows PowerShell

From the repository root:

```powershell
cd serverpulse
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
uvicorn main:app --reload
```

If PowerShell blocks activation, you can skip activation and use the environment's executable directly:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
```

## Run on Linux or macOS

```bash
cd serverpulse
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
uvicorn main:app --reload
```

Open these URLs while the server is running:

- http://127.0.0.1:8000/health
- http://127.0.0.1:8000/metrics
- http://127.0.0.1:8000/alerts
- http://127.0.0.1:8000/docs — interactive API documentation generated by FastAPI

Stop the development server with Ctrl+C.

## Run tests

From inside `serverpulse/`:

```bash
pytest -q
```

## Configuration

The initial version keeps thresholds in `alerts.py` so the logic is easy to find and understand:

- CPU alert: usage at or above 85%
- Memory alert: usage at or above 85%
- Disk alert: usage at or above 90%

These are demonstration defaults, not universal production thresholds. Real systems should use workload-specific thresholds and alert only after sustained conditions to avoid noisy notifications.

## How a request flows

1. A client requests `/metrics` or `/alerts`.
2. FastAPI calls the endpoint function in `main.py`.
3. `collector.py` uses `psutil` to read the current host's metrics.
4. Pydantic models in `models.py` validate and serialize the response.
5. For `/alerts`, `alerts.py` compares metric values with thresholds and returns warning messages.
6. FastAPI sends the result as JSON.

## Important concepts

- **API endpoint:** a URL path that performs a specific operation.
- **Metric:** a numeric measurement such as CPU utilization.
- **Threshold:** a configured boundary used to decide when a warning is appropriate.
- **Pydantic model:** a typed definition that validates the shape of data.
- **Unit test:** a small automated check of one piece of behavior.
- **Polling:** asking for a fresh metric snapshot repeatedly. This version responds only when requested; it does not run a background polling loop.

## Limitations and next steps

This version reads metrics from the machine on which the API runs. It does not yet monitor remote servers, retain historical measurements, send email/Slack alerts, or authenticate users. Good follow-up tasks are:

1. Add a configurable settings file for thresholds.
2. Store timestamped snapshots in SQLite.
3. Add a background collection loop.
4. Build a small dashboard with charts.
5. Add API-key authentication and restrict network access.
6. Add Docker packaging and CI tests.
